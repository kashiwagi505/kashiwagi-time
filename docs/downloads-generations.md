## 7. 穴埋めの記法（全7回で統一）

元資料の `.java` が実際に使っていた記法を採用した。**新しい記法は発明していない。**

### 形1: バナー型 ── 手順が続く場所（main の中など）

```java
        // ================================================
        // ▼▼【TODO①】パーティ用の ArrayList「party」を作成しよう
        // ================================================


```

原本の `04-arraylist/Game.java` `Main.java`、`06-polymorphism/PolyGame.java` がこの形。
`Main.java` は番号が **【問1-1】【問2-6】** のように問題番号、`Game.java` / `PolyGame.java` は **【TODO①】** の通し番号。

### 形2: 1行型 ── クラスやメソッドの中の短い穴

```java
    public double getTime() {
        // ▼▼【TODO②】time を返す
    }
```

原本の `柏木タイム_継承オーバーライド演習問題.md` のヒントが `// ▼▼ ここで親に初期値を渡す（super）` という1行型を使っている。

### 新規作成分に適用したルール

- **マーカーは `// ▼▼【TODO○】`（丸数字の通し番号）に統一。** 元資料の第2回は `// TODO:`、第3回は `// ここに〜を書く` と記法がバラバラだったので、**マーカーだけ統一し、説明の文言は原本の日本語をそのまま維持**した
- 穴が2〜3行以上になる場所は形1（バナー）、1行で済む場所は形2
- 「触ってはいけないファイル」は先頭のコメントに **`（このファイルは変更しない）`** と明記（原本の `Main2.java` `Main3.java` `Maou.java` がこの書き方）
- 各ファイルの先頭に、期待する出力・コンストラクタの形など**そのファイルだけ見れば作業できる情報**を置いた。プロジェクトの内部事情（元資料に無い等）は書いていない
